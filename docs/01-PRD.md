# 文旅消费券平台 PRD（V1.0）

## 1. 项目定位

打造面向游客、商户、景区与政府/城市运营方的「消费票据兑换平台」。

用户通过上传消费票据、景区门票、交通订单等凭证，参与盲盒抽奖、领取消费券、完成打卡任务并获取积分奖励，促进本地消费与二次传播。

## 2. 角色体系

| 角色 | 权限 |
| --- | --- |
| 游客/消费者 | 上传票据、抽奖、领券、打卡、积分兑换 |
| 商户 | 注册门店、扫码验券、查看门店核销数据 |
| 运营人员 | 发券规则、盲盒概率、活动配置、数据统计 |
| 审核人员 | 人工审核票据、复核 AI 结果 |
| 超级管理员 | 系统配置、权限管理 |
| AI 智能体 | OCR、票据分类、防伪、风险评分 |

## 4. 用户场景

### 4.1 餐厅消费

```text
到店消费 → 获得小票 → 小程序上传票据 → AI 审核
→ 盲盒开奖 → 获得消费券 → 下次到店使用 → 获得积分
```

### 4.2 景区消费

```text
购买景区门票 → 上传门票 → 审核通过 → 获得景区折扣券
→ 完成打卡 → 获得积分
```

### 4.3 城市活动

```text
参与活动 → 多点打卡集章 → 兑换限定奖励
```

统一抽象：

```text
verify(code) / issue(user) / consume(code)
```

## 7. 关键业务规则

1. 同一 `order_no + amount + consume_time` 不可重复兑换。
2. 图片 MD5 / 感知哈希命中历史票据时进入风险复核。
3. 盲盒库存必须 Redis 原子扣减，失败则降级为「谢谢参与」或重试。
4. 核销必须幂等：同一 `coupon_code` 只能成功一次。
5. 积分变更必须写流水，禁止只改余额。
6. 打卡默认 GPS 300 米内自动通过，异常用户触发照片抽检。

## 8. 成功指标（上线前门槛）

| 指标 | 目标 |
| --- | --- |
| 票据识别准确率 | ≥ 95% |
| 重复票据拦截率 | ≥ 99% |
| 定位作弊率 | ≤ 3% |
| 抽奖概率与配置一致 | 100% |
| 商户核销幂等 | 100% |

## 9. 非功能需求

- 日活目标：10 万（设计容量）
- 峰值上传：300 TPS
- 峰值抽奖：1000 TPS
- 峰值核销：500 TPS
- 接口统一鉴权、限流、审计日志
- 敏感配置（密钥、AI Key）不得入库明文

## 10. 范围边界

### 做

- 票据上传与 AI/人工审核
- 盲盒发券
- 本地商户核销
- 积分与打卡
- 运营后台

### 不做（一期）

- 完整支付结算
- 商户资金分账
- 视频流实时核验
- 完整城市大脑画像

## 11. 验收口径（MVP）

1. 用户可完成「上传 → 审核 → 开盲盒 → 领券 → 核销 → 得积分」闭环。
2. 商户可注册门店并完成扫码核销。
3. 后台可配置发券/积分/盲盒规则，并查看三类统计。
4. 重复票、已用券、过期券均被正确拦截。
